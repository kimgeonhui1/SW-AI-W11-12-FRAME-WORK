# JUNGLE POKER LAB — 2인 온라인 대전 (방 방식)

작성 2026-11-16. 기존 연습 모드(`poker.html`, 사람 1명 대 봇)는 그대로 두고, 사람 2명이 같은 방에서 대전하는 모드를 추가했다. 가상 칩만 사용한다.

## 한 번의 행동이 지나가는 길

플레이어 행동 → 서버 처리 → 저장/전파 → 두 화면 변화

1. **행동**: 화면은 `POST /api/rooms/{코드}/action`으로 요청만 보낸다. 요청에는 고유한 `action_id`와, 화면이 보고 있던 `expected_version`이 들어 있다.
2. **서버 처리**: 방 하나의 잠금 안에서 순서대로 처리한다. 토큰으로 좌석 소유자를 확인하고, 같은 `action_id`면 다시 적용하지 않고, 버전이 다르면 거절한다. 덱·턴·합법 행동·칩·팟·승패는 기존 2인 `PokerEngine`이 판정한다.
3. **저장/전파**: 핸드가 끝나면 `hand_results`에 한 번만 저장한다(기존 insert-once). 공개 정보는 Mini Redis에 쓴다. 대기 중이던 두 사람의 `GET .../state` 요청이 같은 번호의 이벤트와 새 버전을 받는다.
4. **두 화면**: 각자 이벤트를 번호 순서대로 재생하고, 끝나면 서버 상태와 똑같이 맞춘다. 본인 좌석은 항상 아래쪽이다.

## 엔진 재사용

2인 엔진을 수정 없이 쓴다. 0번 좌석이 엔진의 `human`, 1번 좌석이 `bot` 자리다(저장 기록의 이름일 뿐 둘 다 사람이다). 3인 이상은 엔진·정산·저장 형식이 모두 바뀌므로 별도 확장이다.

## API (`rooms.py`, 모두 `Authorization: Bearer <게스트 토큰>` 필요. `public`만 예외)

| 요청 | 내용 |
|---|---|
| `POST /api/rooms` `{request_id}` | 방 생성, 만든 사람이 0번 좌석 |
| `POST /api/rooms/{코드}/join` `{}` | 참가. 이미 앉은 사람이 다시 부르면 본인 좌석으로 복귀 |
| `POST /api/rooms/{코드}/ready` `{ready, hand_no}` | 준비. 둘 다 준비하면 매치 또는 다음 핸드 시작 |
| `POST /api/rooms/{코드}/action` `{action_id, expected_version, action, to?}` | fold / check / call / bet / raise / all_in |
| `GET /api/rooms/{코드}/state?since=&after=&wait=` | 본인 시점 상태. 바뀔 때까지 최대 5초 기다렸다 응답(long polling) |
| `GET /api/rooms/{코드}/public` | 참가 전 미리보기(이름·인원·칩·보드). Mini Redis에서 먼저 읽음 |
| `POST /api/rooms/{코드}/leave` `{}` | 시작 전에만 자리 비우기 |

방 코드는 방을 찾는 데만 쓴다. 좌석을 조작할 권한은 그 좌석에 앉은 게스트 토큰에만 있다.

## 정한 규칙

- **카드 비공개**: 응답·이벤트에는 본인 홀카드만 들어간다. 상대 카드는 쇼다운 때만 전달되고, 폴드로 끝나면 끝까지 전달되지 않는다. 덱과 공개 캐시에는 홀카드가 없다.
- **중복·지난 요청**: 같은 `action_id` 재전송은 한 번만 적용. 다른 내용으로 같은 ID를 쓰면 409. `expected_version`이 현재와 다르면 409 `stale_state`와 최신 상태를 돌려준다.
- **시간 제한**: 차례당 30초, 서버 시계로만 판정한다. 넘기면 체크, 베팅을 받은 상태면 폴드. 방을 보는 요청이 들어올 때 적용된다.
- **끊김**: 8초 동안 상태 요청이 없으면 "연결 끊김"으로 표시. 진행 중인 핸드는 시간 제한대로 계속되고, 다음 핸드는 두 사람이 모두 접속해 있을 때만 시작한다.
- **새로고침·재접속**: 같은 브라우저(같은 토큰)로 다시 들어오면 본인 좌석과 최신 상태를 받는다. 탭을 두 개 열면 같은 좌석을 보며, 먼저 도착한 요청만 반영된다.
- **다음 핸드**: 둘 다 "다음 판 준비"를 누르면 바로, 아니면 12초 뒤 자동 시작.
- **매치 종료**: 한쪽 칩이 0이 되면 끝. 방 하나가 매치 하나다. 다시 하려면 새 방을 만든다.

## 무엇이 언제 저장되는가

| 시점 | DBMS | 복구 가능 범위 |
|---|---|---|
| 둘 다 준비 → 매치 시작 | `matches` 한 행(방 코드에서 만든 키, 두 좌석의 게스트 ID) | 좌석 소유자 |
| 핸드 종료 | `hand_results` 한 행(시작·종료 칩, 승자, 보드, 공개 행동) | 그 핸드까지의 칩 |
| 핸드 진행 중 | 저장하지 않음(덱·베팅은 메모리) | **복구 불가** |
| 시작 전 로비 | 저장하지 않음 | **복구 불가** |

- 매치 행을 저장하지 못하면 시작하지 않는다. 핸드 결과 저장이 확인되지 않으면 다음 핸드를 막고 같은 행을 다시 시도한다.
- **서버 재시작**: 방 코드로 `matches`와 `hand_results`를 읽어 좌석과 마지막 확정 칩을 되살린다. 진행 중이던 핸드는 무효다. 완료 핸드 저장만으로 진행 중 게임이 복구되는 것은 아니다.

## Mini Redis의 역할

- 키 `poker:room:{코드}`, TTL 30초. 방 상태가 바뀔 때마다 공개 정보를 다시 쓴다.
- 읽는 곳: 참가 전 미리보기(`/public`). 있으면 HIT, 없으면 메모리에서 만들어 다시 채운다(MISS).
- Redis가 꺼져 있으면 5초 동안 건너뛰고(BYPASS) 게임은 그대로 진행한다. 게임 판정과 DBMS 기록은 Redis를 읽지 않는다.
- 쓰기에 실패한 직후에는 미리보기가 최대 TTL만큼 옛 값일 수 있다.

## 실행

네 프로세스를 **한 컴퓨터(서버 역할)** 에서 띄운다. DBMS와 Redis는 그 컴퓨터 안에서만 쓰므로 `127.0.0.1`로 둔다.

```
projects/dbms        python -m mini_dbms.server --data-dir <데이터 폴더> --host 127.0.0.1 --port 18783
projects/redis       python -m mini_redis.server --host 127.0.0.1 --port 6382
projects/poker_demo  python server.py --host <바인드 주소> --port 18784 --dbms http://127.0.0.1:18783 --redis http://127.0.0.1:6382
projects/react       python -m http.server 5500 --bind <바인드 주소>
```

화면은 페이지를 연 주소의 호스트로 API(18784 포트)를 찾는다. 다른 주소를 쓰려면 `room.html?api=http://주소:포트`.

### 같은 PC에서 두 창으로 시험

`<바인드 주소>`를 `127.0.0.1`로 두고 `http://127.0.0.1:5500/room.html`을 연다. 같은 브라우저의 두 탭은 같은 게스트가 되므로, 두 번째 사람은 시크릿 창·다른 브라우저를 쓰거나 `room.html?guest=2`로 연다. 이 방법은 서로 다른 컴퓨터 접속을 확인해 주지 않는다.

### 같은 공유기(LAN)의 두 컴퓨터

1. `<바인드 주소>`를 `0.0.0.0`으로 띄운다. `127.0.0.1`로 띄우면 다른 컴퓨터에서 접속할 수 없다.
2. 서버 컴퓨터의 IPv4 주소를 확인한다(Windows `ipconfig`, 예: `192.168.0.7`).
3. 서버 컴퓨터의 방화벽에서 5500, 18784 포트의 인바운드를 허용한다.
4. **두 컴퓨터 모두** `http://192.168.0.7:5500/room.html`을 연다(서버 컴퓨터도 `localhost` 대신 이 주소를 쓴다).

### 인터넷(서로 다른 네트워크)

현재 배포하지 않았으므로 인터넷 플레이는 되지 않는다. 필요하면 공인 주소를 가진 서버(또는 포트 포워딩·터널)에 위 네 프로세스를 올려야 하고, 게스트 토큰이 평문으로 지나가지 않도록 HTTPS가 있어야 한다. 요청 수 제한 같은 공개 서비스용 보호는 없다.
