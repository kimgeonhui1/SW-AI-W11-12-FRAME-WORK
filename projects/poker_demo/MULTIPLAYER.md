# JUNGLE POKER LAB — 2~4인 온라인 대전 (방 방식)

작성 2026-11-16, 2~4인 확장 2026-11-17, 규칙 v2(파산 뒤 1회 지급·행동 표시) 2026-11-17. 연습 모드(`poker.html`, 사람 1명 대 봇)는 그대로 두고, 사람 2~4명이 같은 방에서 대전한다. 가상 칩만 사용한다.

## 한 번의 행동이 지나가는 길

1. **행동**: 화면은 `POST /api/rooms/{코드}/action`으로 요청만 보낸다. 요청에는 고유한 `action_id`와 화면이 보고 있던 `expected_version`이 들어 있다.
2. **서버 처리**: 방 하나의 잠금 안에서 순서대로 처리한다. 토큰으로 좌석 소유자를 확인하고, 같은 `action_id`면 다시 적용하지 않고, 버전이 다르면 거절한다. 덱·턴·합법 행동·칩·팟·승패는 `table.TableHand`(2~4인 엔진)가 판정한다. 패 족보 비교는 기존 `engine.py`를 그대로 쓴다.
3. **저장/전파**: 핸드가 끝나면 `room_hand_results`에 한 번만 저장한다(insert-once). 공개 정보는 Mini Redis에 쓴다. 대기 중이던 모든 좌석의 `GET .../state`가 같은 번호의 이벤트와 새 버전을 받는다.
4. **화면**: 각자 이벤트를 번호 순서대로 재생하고, 끝나면 서버 상태와 똑같이 맞춘다. 본인 좌석은 항상 아래, 나머지는 테이블 순서대로 왼쪽 → 위 → 오른쪽.

## 파일

| 파일 | 역할 |
|---|---|
| `table.py` | 2~4인 한 핸드: 버튼·블라인드·행동 순서·최소 레이즈·올인 재오픈·메인/사이드 팟·정산 |
| `rooms.py` | 방·좌석·준비·시작·참가/퇴장·타임아웃·저장·복구·Redis 미리보기 |
| `server.py` | HTTP 라우팅, 전적(`/api/profile`)에 2~4인 기록 합산, 끊긴 연결에 두 번째 응답을 쓰지 않음(D2 수정) |
| `engine.py` | 연습 모드 2인 엔진. 수정하지 않았고, 족보 평가만 `table.py`가 가져다 쓴다 |

## API (`Authorization: Bearer <게스트 토큰>` 필요. `public`만 예외)

| 요청 | 내용 |
|---|---|
| `POST /api/rooms` `{request_id, max_seats?}` | 방 생성. `max_seats` 2~4(기본 4). 만든 사람이 0번 좌석이자 방장 |
| `POST /api/rooms/{코드}/join` `{}` | 빈 좌석 중 가장 앞 번호에 앉는다. 이미 앉은 사람이 다시 부르면 본인 좌석으로 복귀 |
| `POST /api/rooms/{코드}/ready` `{ready, hand_no}` | 로비: 준비. 핸드 사이·진행 중 비참가자: 다음 핸드 참가 예약 |
| `POST /api/rooms/{코드}/start` `{hand_no: 0}` | 방장만. 준비한 사람이 2명 이상이면 그 사람들로 시작 |
| `POST /api/rooms/{코드}/next-round` `{hand_no}` | `round_over`일 때 앉은 누구나. 파산자마다 1,000칩 1회 지급 후 이어감 |
| `POST /api/rooms/{코드}/action` `{action_id, expected_version, action, to?}` | fold / check / call / bet / raise / all_in |
| `GET /api/rooms/{코드}/state?since=&after=&wait=` | 본인 시점 상태. 바뀔 때까지 최대 5초 기다렸다 응답(long polling) |
| `GET /api/rooms/{코드}/public` | 참가 전 미리보기(이름·인원·칩·보드, 카드 없음). Mini Redis에서 먼저 읽음 |
| `POST /api/rooms/{코드}/leave` `{}` | 로비: 자리 비우기. 매치 중(내가 든 핸드 밖): 칩 정산 후 퇴장 → `cashOut` |

방 코드는 방을 찾는 데만 쓴다. 좌석을 조작할 권한은 그 좌석에 앉은 게스트 토큰에만 있다. 다른 방의 토큰은 403 `not_seated`.

## 방·좌석 규칙

- **인원**: 방마다 2~4석. 시작에는 준비한 사람 2명 이상이 필요하다.
- **시작**: 앉은 사람이 모두 준비하면 바로 시작. 그 전이라도 준비한 사람이 2명 이상이면 방장이 시작할 수 있고, 준비하지 않은 사람은 앉은 채로 다음 핸드부터 참가한다.
- **방장**: 방을 만든 사람. 로비에서 방장이 나가면 다음 좌석으로 넘어간다. 방장의 권한은 로비에서의 시작뿐이다.
- **이번 핸드 참가자는 고정**: 핸드 시작 때 정한 참가자만 카드를 받는다. 진행 중에 들어온 사람은 바로 1,000칩을 받고 앉되(기록됨) 다음 핸드부터 참가한다.
- **다음 핸드**: 참가 예약한 사람(직전 핸드 참가자 포함)이 모두 "다음 판 준비"를 누르면 바로, 아니면 12초 뒤 준비한 사람끼리 자동 시작. 칩이 있고 접속 중인 사람만 포함된다.
- **나가기**: 로비에서는 자리만 비운다. 매치가 시작된 뒤에는 칩을 정산(`leave` 기록)하고 나가며, 같은 매치에는 다시 앉을 수 없다(409 `left_match`). 자기가 든 핸드 도중에는 나갈 수 없다(409 `match_in_progress`, 창을 닫으면 시간 제한대로 처리).
- **칩 0 (규칙 v2)**: 핸드 H에서 칩이 0이 된 사람은 좌석과 접속을 그대로 유지하고, **다음 핸드 H+1 한 번을 관전**한다. H+1의 결과가 저장되면 다음 핸드 시작 전에 **1,000칩을 1회 지급**(`rebuy` 기록)받고 자동으로 다시 참가한다. 준비 요청·새로고침·재접속·중복 요청으로 대기를 줄일 수 없고(서버가 핸드 번호로만 판단), 지급 기록은 파산마다 하나의 고유 키라 두 번 지급되지 않는다.
- **다음 라운드 시작**: 칩 가진 사람이 1명 이하라 관전할 H+1을 열 수 없으면 방은 `round_over`에서 기다린다. 앉아 있는 **누구나**(방장이 파산했거나 자리를 비웠을 수 있으므로) "다음 라운드 시작"을 누를 수 있다. 칩 보유자의 칩은 그대로, 파산자에게만 1,000칩을 1회 지급하는 예외다. 요청은 핸드 번호에 묶여 있어 두 번째 누름·동시 누름은 409 `not_round_over`로 아무것도 바꾸지 않는다. 파산자가 없고 혼자 남았으면 새로 들어올 사람을 기다린다.
- **매치 종료 없음**: 예전의 "칩 보유자 1명 이하 = 매치 종료"는 위 두 규칙으로 바뀌었다. 방은 모두 나갈 때까지 이어진다.
- **끊김**: 8초 동안 상태 요청이 없으면 "연결 끊김". 진행 중인 핸드는 시간 제한대로 계속되고, 끊긴 사람은 다음 핸드에서 빠진다(칩은 그대로).
- **방 하나 = 매치 하나**: 다시 하려면 새 방을 만든다.

## 게임 규칙 (No-Limit Texas Hold'em, 블라인드 10/20)

기준은 Poker TDA 규칙이다. 다른 점은 "하우스 규칙"으로 따로 적었다.

| 항목 | 구현 |
|---|---|
| 버튼·블라인드 | 3~4인: 버튼 → SB → BB. 프리플롭은 BB 다음(3인이면 버튼)부터, 플롭 이후는 버튼 왼쪽 첫 생존자부터 |
| 헤즈업 예외 | 버튼이 SB이고 프리플롭 먼저, 플롭 이후 마지막 (TDA "Button in Heads-up") |
| 행동 차례 | 폴드·올인한 좌석은 건너뛴다. 모두 행동했고 살아 있는 사람의 베팅이 같거나 올인이면 라운드 종료 |
| 최소 레이즈 | 직전의 "완전한" 베팅/레이즈 크기 |
| 짧은 올인 | 완전한 레이즈보다 작은 올인은 이미 행동한 사람에게 레이즈를 다시 열지 않는다. 여러 짧은 올인이 합쳐 완전한 레이즈 이상이 되면 다시 연다 (TDA) |
| 사이드 팟 | 올인 금액마다 팟을 나누고 팟마다 따로 정산(TDA "Side Pots"). 폴드한 사람의 칩은 팟에 남지만 받을 자격은 없다 |
| 초과 베팅 | 아무도 맞추지 못한 금액은 낸 사람에게 돌려준다(`returned` 이벤트) |
| 무승부·홀수 칩 | 팟을 균등 분배, 나머지 칩은 버튼 왼쪽부터 가까운 승자에게 1개씩 (TDA "Odd Chips") |
| 진행 중 팟 표시 | 올인한 사람이 있을 때만 사이드 팟으로 나눠 보여 준다. 블라인드·아직 안 맞춘 베팅은 하나의 팟 |
| 모두 올인 | 남은 보드를 끝까지 깔고 쇼다운 |

하우스 규칙(TDA와 다르거나 TDA가 정하지 않은 것):

- **움직이는 버튼**: 버튼은 이번 핸드 참가자 중 직전 버튼 다음 좌석으로 간다. TDA 토너먼트의 dead button(빠진 좌석 자리에 버튼을 두는 방식)은 쓰지 않는다. 그래서 사람이 빠지거나 들어오면 블라인드를 연속으로 내거나 건너뛰는 경우가 생긴다.
- **짧은 BB**: BB가 20보다 적게 남아 올인으로 내도 콜 금액은 20이다. 남는 초과분은 라운드 끝에 돌려준다.
- **승·패·무 집계**: 전적은 핸드마다 "그 핸드의 칩 증감"으로 센다(+ 승, − 패, 0 무). 지급(리바이)은 핸드 밖의 기록이라 승리·수익으로 세지 않고 `rebuys`로 따로 센다.
- **파산 뒤 지급(리바이)**: 위 "칩 0" 규칙. TDA에는 없는 연습용 규칙이다. 무료 지급이 있으므로 누적 칩을 그대로 랭크 점수로 쓰면 안 된다(랭크는 후속 작업).
- **시간 제한**: 차례당 30초, 서버 시계로만 판정. 넘기면 체크, 베팅을 받은 상태면 폴드.
- **카드 공개**: 쇼다운까지 남은 사람의 카드만 모두에게 공개. 폴드한 카드는 끝까지 전달하지 않는다(머킹 순서·보여 주기 선택은 없음).

참고: Poker TDA Rules — https://www.pokertda.com/ (Button in Heads-up, Side Pots, Odd Chips, all-in 재오픈 규칙).

## 무엇이 언제 저장되는가 (Mini DBMS, 기존 테이블은 그대로 두고 새 테이블 3개 추가)

| 시점 | 테이블 | 복구 가능 범위 |
|---|---|---|
| 매치 시작 | `room_matches` 1행 + 앉은 사람마다 `room_seat_events`(`buyin` 1,000) | 좌석 소유자·바이인 |
| 매치 중 참가 | `room_seat_events`(`buyin`, `after_hand`=완료 핸드 수) | 그 좌석 |
| 매치 중 퇴장 | `room_seat_events`(`leave`, 그때의 칩) | 정산액·재착석 금지 |
| 파산 뒤 지급 | `room_seat_events`(`rebuy`, 1,000, `after_hand`=관전한 핸드 또는 다음 라운드 시작 때의 핸드). 키 `…:seat:{user}:rebuy:{파산 핸드}` | 지급액·대기 상태 |
| 핸드 종료 | `room_hand_results` 1행: 참가자별 시작·종료 칩, 버튼, 팟별 금액·자격·승자·배분, 보드, 공개 행동, 직전 결과 ID | 그 핸드까지의 칩 |
| 핸드 진행 중·로비 | 저장하지 않음 | **복구 불가** |

- 모든 행은 고유 키로 한 번만 들어간다(같은 내용 재시도는 성공, 다른 내용이면 409로 방을 멈춤).
- 바이인·퇴장 기록이 저장되지 않으면 그 참가·퇴장은 일어나지 않은 것으로 하고 503을 돌려준다. 핸드 결과 저장이 확인되기 전에는 다음 핸드·참가·퇴장을 막고 같은 행을 다시 시도한다. 지급 기록도 같다: 확인되기 전에는 칩을 주지 않고, 다음 핸드·참가·퇴장을 막고, 같은 행을 다시 시도한다.
- **검증(`replay_ledger`)**: 기록을 처음부터 다시 계산해 해시·연결(직전 결과 ID)·핸드마다 칩 보존·"테이블 칩 합 = 바이인 합 + 지급 합 − 정산 합"을 확인한다. 지급은 칩 0인 좌석에, 파산 뒤 한 핸드를 관전한 다음이거나(다음 라운드 시작 예외) 칩 보유자가 1명 이하일 때만 유효하다. 어긋나면 복구하지 않는다.
- **서버 재시작**: 방 코드로 기록을 읽어 좌석·칩·퇴장자·버튼·방장·파산 대기 상태를 되살린다. 진행 중이던 핸드는 무효이고 마지막으로 저장된 칩에서 이어간다. 지급 시점이 지났는데 기록이 없으면 같은 행으로 지급한다(이미 있으면 다시 주지 않음).
- **기존 데이터**: 이전 2인 방의 `matches`/`hand_results`는 읽기만 하며 전적에 계속 합산된다. 이전 방식의 진행 중 방은 새 서버에서 복구되지 않는다. 규칙 v1로 저장된 2~4인 방(`rebuy` 행 없음)도 그대로 읽히며, 칩 0인 좌석은 복구 뒤 v2 규칙(관전 후 지급 또는 다음 라운드 시작)을 따른다. 테이블은 새로 추가하지 않았다.

## 화면 표시 (규칙 v2와 함께 바뀐 것)

- **좌석 행동 표시**: 이름표 안에 이번 스트리트의 마지막 행동을 크게 보여 준다. `콜 +40`은 이번에 더 낸 금액, `베팅 총 100`·`레이즈 총 300`·`올인 총 1,120`은 이번 스트리트에 낸 총액이다. 칩을 모두 냈지만 현재 베팅에 못 미치면 `올인 콜 +X`. 시간 초과 자동 처리는 `(시간 초과)`.
- **초기화 시점**: 새 핸드 시작 때 모두 지우고 블라인드(`SB 10`, `BB 20`)만 표시, 새 스트리트에서는 폴드·올인만 남기고 지운다. 핸드가 끝나도 다음 핸드가 시작될 때까지 남긴다. 새로고침해도 서버 이벤트로 같은 표시를 다시 만든다.
- **최근 행동 기록**: 이번 핸드의 최근 5개. 넓은 화면은 테이블 중앙 위, 720px 이하는 테이블 아래.
- **결과**: `내 칩 · 시작 1,000 → +216 → 현재 1,216 · 팟 수령 236 / 순이익 +216`. 팟 수령에는 내가 넣은 칩이 돌아온 몫도 들어 있고, 순이익은 핸드 시작·끝 칩의 차이다. 지급을 받았으면 `지급 +1,000(수익 아님)`. 각 좌석 이름표에도 `이번 핸드 ±X`.
- **베팅 한도**: 입력창 옆에 `콜 40 · 최소 레이즈 총 120 · 최대 총 600`. 최소 정식 레이즈보다 적은 올인은 `올인 총 90 (최소 레이즈 120보다 적지만 올인은 허용)`. 범위 밖 입력은 버튼을 잠그고 이유를 보여 주며, 서버도 같은 범위로 거절한다(400 `illegal_action`). 내 차례가 아닐 때·핸드 사이·요청 처리 중에는 행동 버튼이 없거나 잠기고, 서버가 4xx로 거절하면 최신 상태로 맞춘 뒤 다시 누를 수 있다.
- **파산 대기**: 좌석 배지 `5번 핸드 관전 후 복귀` → `관전 중 · 이 핸드 뒤 복귀` → 지급 뒤 사라짐. `round_over`에서는 모두에게 `다음 라운드 시작` 버튼. 명시적인 `칩 정산하고 나가기`·`로비로 (자리 유지)` 말고는 방을 나가는 버튼이 없다.

## Mini Redis의 역할

- 키 `poker:room:{코드}`, TTL 30초. 방 상태가 바뀔 때마다 공개 정보(이름·인원·칩·보드, 홀카드 없음)를 다시 쓴다.
- 읽는 곳: 참가 전 미리보기(`/public`). 게임 판정과 DBMS 기록은 Redis를 읽지 않는다. Redis가 꺼져 있으면 5초 동안 건너뛴다.
- 미리보기가 옛 값이어도 좌석은 서버가 정한다(꽉 찬 방이면 409 `room_full`).

## 실행

네 프로세스를 **한 컴퓨터(서버 역할)** 에서 띄운다. DBMS와 Redis는 그 컴퓨터 안에서만 쓰므로 `127.0.0.1`로 둔다.

```
projects/dbms        python -m mini_dbms.server --data-dir <데이터 폴더> --host 127.0.0.1 --port 18783
projects/redis       python -m mini_redis.server --host 127.0.0.1 --port 6382
projects/poker_demo  python server.py --host <바인드 주소> --port 18784 --dbms http://127.0.0.1:18783 --redis http://127.0.0.1:6382
projects/react       python -m http.server 5500 --bind <바인드 주소>
```

- **같은 PC 시험**: `<바인드 주소>`=`127.0.0.1`, `http://127.0.0.1:5500/room.html`. 사람마다 다른 브라우저·시크릿 창 또는 `room.html?guest=2`, `?guest=3`, `?guest=4`. 이 방법은 서로 다른 컴퓨터 접속을 확인해 주지 않는다.
- **같은 공유기(LAN)의 2~4대**: `<바인드 주소>`=`0.0.0.0`, 서버 컴퓨터 방화벽에서 5500·18784 인바운드 허용, **모든 컴퓨터**가 `http://<서버 IPv4>:5500/room.html`을 연다.
- **인터넷**: 배포하지 않았다. 공인 주소·HTTPS·요청 수 제한이 필요하다.
