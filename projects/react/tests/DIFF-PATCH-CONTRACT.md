# Part 1 diff/patch 계약

2026-11-10 · 사용자 승인에 따라 자식 비교 계약을 제한적으로 수정했다.

## 요구의 출처와 범위

- 사용자 지정 필수 검증: 같은 VDOM의 DOM 조작 없음, Text 유지, props 추가·수정·제거, type 교체, 자식 추가·삭제와 중첩 변경, 변경 없는 형제 보존, 실제 브라우저·회귀 검사.
- 저장소 README 규칙: 공통 파일명·함수명·VNode 형식 유지, Live Server 실행.
- 공식 LMS 원문은 아직 미확인이다. 위 사용자 요구나 아래 자체 설계 규칙을 공식 과제 원문으로 단정하지 않는다.
- 자체 설계 계약: 이전 트리 경로, 전용 컨테이너, 정확한 서브트리 대응 및 중복 tie-break, null 루트, 주석 처리. LCS나 중복 대응 방식 자체가 과제 필수 알고리즘이라는 뜻은 아니다.

## 지원 및 적용 계약

- 기존 `h`, `domToVdom`, `createElement`, VNode 형식과 함수명을 유지한다.
- HTML 요소 `{ type, props, children }`, 문자열 Text, 문자열 HTML 속성을 지원한다.
- `null`은 루트의 부재를 표현한다. children 안에는 유효한 요소/문자열만 넣는다.
- 이벤트 props, live form property, SVG, keyed reorder는 지원 범위 밖이다.
- `diff(oldVNode, newVNode)`는 입력/DOM을 변경하지 않고 연산 배열을 반환한다.
- `patch(container, patches)`의 container는 지원 대상 루트 0~1개를 담는 전용 컨테이너이다. container 자체는 비교 대상이 아니며 반환값은 갱신된 루트 또는 null이다.
- 경로 `[]`는 루트, `[1,0]`은 루트의 두 번째 자식의 첫 번째 자식이다. 경로는 이전 트리 기준이고, 주석은 기존 domToVdom 규약처럼 인덱스에서 제외한다.
- 연산은 `text(value)`, `props(set, remove)`, `replace(vnode)`, `remove`, `insert(vnode)`이다. insert 경로는 이전 자식 앞의 삽입 위치이며 끝 인덱스는 append다. 같은 위치에 여러 삽입은 목록 순서대로 수행한다.
- patch는 모든 이전 DOM 참조를 먼저 확보하고 순서대로 적용한다. 같은 VDOM은 빈 연산 목록이며 Text는 `.data`, props는 달라진 속성만 갱신한다.
- 자식은 type·props·자식 순서·모든 후손이 같은 서브트리의 최장 공통 부분수열(LCS)을 앵커로 대응한다. 앵커는 순서대로 일대일 보존한다. 속성 열거 순서는 무관하다.
- 중복은 현재 쌍이 같으면 즉시 대응한다. 가능한 대응 개수가 같으면 이전 트리의 앞쪽 후보를 우선 남긴다. 동일한 두 노드 중 사용자가 의미상 어느 노드를 삭제했는지는 key 없이 판별할 수 없다.
- 앵커 사이 구간은 위치 비교한다. 단, 길이가 다르고 현재 type이 다르면 길이 차이만큼의 범위에서 첫 같은 type을 찾고 그 앞의 잉여 노드를 먼저 삽입/삭제한다. 같은 type은 업데이트 후보일 뿐 동일 서브트리로 간주하지 않으며, 반드시 재귀 비교한다.
- 이전 트리의 경로와 patch 연산 종류는 그대로다. key 기반 정체성, move 연산, 전체 트리의 최소 DOM 연산 수는 보장하지 않는다.
- 잘못된 VNode, 외부에서 변경한 DOM, 중복 적용은 계약 밖이다. 잘못된 경로/노드 종류는 적용 전에 검사하지만 전체 DOM과 이전 VDOM의 동등성, 임의 수제 patch의 원자성까지 보장하지 않는다.

## 해결한 반례와 남은 한계

이전: `<div><i>A</i><b>B</b></div>`

다음: `<div><u>X</u><i>A</i><b>B2</b></div>`

이전 방식은 동일 suffix가 없어 i를 교체했다. 현재는 i가 정확한 앵커가 되어 `root.childNodes[1] === oldI`이고 b 및 Text도 유지된다. 기존 실패 테스트의 기대값은 그대로다.

- 각 자식 목록 길이 n,m에 대해 LCS 메모리는 O(n×m), 시간은 O(n×m×서브트리 동등성 비교 비용)이다. 대규모 성능 검증은 하지 않았다.
- 동일 중복이나 모두 변경된 같은 type 형제의 의미상 identity는 추론하지 않는다. 예: 동일 i 두 개를 하나로 줄이면 앞쪽 객체를 남긴다. 순서를 바꾸는 경우 모든 객체 보존은 지원하지 않는다.
