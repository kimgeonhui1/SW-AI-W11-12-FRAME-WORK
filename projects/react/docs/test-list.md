### diff 에 잘못된 VNode

- undefined
- 숫자
- 불리언
- 배열
- 빈 객체
- type 빈 문자열

### patch 가 거부하는 입력

## Phase 2

### FunctionComponent 기본

- component 가 함수가 아니거나 container 가 요소가 아니면 TypeError
- 만들 때 hooks 는 빈 배열, mount() 는 자기 자신을 돌려주고 렌더 횟수 1
- mount 는 컨테이너에 원래 있던 내용을 바꿔 넣는다
- 컴포넌트가 돌려주는 값: 문자열 · 숫자 · 배열 · 중첩 배열 · null · false
- 루트 컴포넌트는 세 번째 인자 props 를 받는다
- 이미 마운트했으면 mount() 오류, 마운트 전 update() 오류
- update 는 Diff/Patch 로 바뀐 텍스트만 고치고 나머지 노드는 그대로 재사용
- 바뀐 것이 없으면 패치 0개, DOM 그대로
- 렌더 결과 VDOM 은 Phase 1 형식 그대로 (containerToVdom 과 같음)
- 여러 루트는 서로 독립 (hooks · 렌더 횟수 따로)
- 렌더 도중 다른 루트를 렌더하면 오류
- 순환 참조된 VNode 를 돌려주면 오류, 컨테이너 그대로

### 렌더 오류와 원자성

- 렌더 중 예외 → update 가 예외, 실제 DOM 그대로, 다음 렌더는 정상
- 잘못된 VNode(함수 prop) → TypeError, 실제 DOM 그대로
- 첫 렌더 실패 → 컨테이너 그대로, hooks 비워 둠
- 렌더 실패 시 그 렌더에서 예약된 effect 는 실행되지 않음

### stateless 자식 컴포넌트

- 자식은 props 를 받아 VNode 를 돌려주는 함수, 이름 유지
- props 없이 불러도 빈 객체
- 함수가 아니면 TypeError
- 자식 안에서 Hook 을 부르면 오류 (Hook 은 최상위에서만), 컨테이너 그대로
- 자식이 끝난 뒤에는 루트에서 Hook 을 계속 쓸 수 있음
- 자식 안에서 예외가 나도 '자식 렌더 중' 표시가 풀려 다음 렌더는 정상
- Lifting State Up: 자식이 부모의 콜백을 불러 부모 상태를 바꾼다

### 이벤트 위임

- 이벤트 이름 변환: onClick→click, onKeyDown→keydown, onFocus→focusin, onBlur→focusout, onDoubleClick→dblclick
- VDOM 에는 함수 대신 data-on-click 문자열, 실제 DOM 에 onclick 속성 없음
- 클릭하면 핸들러가 이벤트 객체와 함께 불림
- 안쪽 요소를 클릭해도 바깥 핸들러가 불림 (버블링), 안쪽부터
- stopPropagation() 을 부르면 바깥 핸들러는 불리지 않음
- 핸들러는 항상 최신 렌더의 함수 (최신 상태를 봄)
- 핸들러가 매 렌더 새 함수여도 패치는 생기지 않음 (번호가 같음)
- 이벤트 종류마다 컨테이너 리스너는 하나 (요소가 많아도)
- onClick 이 null · undefined · false 면 핸들러 없음 (속성도 없음)
- onClick 이 문자열이면 TypeError (문자열 코드를 실행하지 않음)
- on 으로 시작해도 대문자가 아니면 일반 속성 (oncology 같은 이름)
- 이벤트가 일어난 요소가 사라진 뒤에도 오류 없음
- extractHandlers 는 원래 트리를 바꾸지 않는다 (useMemo 로 재사용하는 VNode 보호)

### 폼 요소 (제어 컴포넌트)

- 사용자가 입력한 input 도 상태로 값을 바꾸면 화면 값이 바뀜 (value 프로퍼티 동기화)
- checked: true → false 로 바뀌면 체크가 풀림
- checked 속성이 아예 사라지는 경우(PROPS remove)도 체크가 풀림
- option 의 selected 로 select 의 선택이 바뀜
- 값이 같으면 value 프로퍼티를 다시 쓰지 않음 (입력 중 커서 위치 유지)

### unmount · onCommit

- unmount: effect 정리, 컨테이너 비움, 리스너 제거, 이후 setState 무시
- unmount 를 두 번 불러도 정리는 한 번, 다시 mount 는 오류
- onCommit: mount · update 때마다 정보 전달, 구독 해제 가능
- onCommit 구독자가 오류를 내도 렌더와 effect 는 계속

### 검사 횟수 최적화

- mount 에서 잘못된 VDOM 을 막는다 (update 가 이전 VDOM 검사를 건너뛰므로)

### useState

- 초깃값으로 시작, hooks 배열에 저장
- 함수를 넘기면 첫 렌더에서 한 번만 실행 (지연 초기화)
- setState 하면 다시 렌더되고, 함수는 다시 실행돼도 값이 유지된다
- setState 함수는 렌더가 바뀌어도 같은 함수
- 같은 값(Object.is)이면 다시 렌더하지 않음 — NaN 도 같은 값
- 객체는 내용이 같아도 새 객체면 다시 렌더 (참조 비교)
- 배칭: setState 를 3번 불러도 렌더는 1번
- 함수형 업데이트 3번 → +3, 값 업데이트 3번 → +1 (React 와 같음)
- 서로 다른 상태 여러 개를 바꿔도 렌더는 1번
- 렌더 도중 setState → 오류 (무한 렌더 방지), DOM 그대로
- 렌더 밖에서 Hook 을 부르면 오류
- 비동기(setTimeout)에서 setState 해도 반영
- flush() 로 예약된 렌더를 바로 실행 · 예약이 없으면 아무것도 안 함

### Hook 규칙

- 조건에 따라 Hook 순서가 바뀌면 오류, DOM 그대로
- 이전보다 Hook 을 적게 부르면 오류
- 이전보다 Hook 을 많이 부르면 오류
- 오류 뒤에도 원래 순서로 렌더하면 정상 동작

### useEffect

- 렌더 중이 아니라 화면 반영 뒤에 실행 (effect 안에서 새 DOM 을 읽을 수 있음)
- deps 없음 → 매 렌더 실행
- deps [] → 처음 한 번만
- deps 값이 바뀔 때만 다시 실행 (Object.is 비교)
- deps 길이가 바뀌어도 다시 실행
- 다시 실행하기 전에 이전 cleanup 먼저, 순서는 선언 순서
- cleanup 은 이전 렌더의 값을 기억한다 (클로저)
- 언마운트하면 모든 cleanup 실행
- effect 가 함수가 아닌 값을 돌려주면 cleanup 으로 쓰지 않음
- effect 안에서 setState → 렌더 1번 더 (deps 로 멈춤)
- effect 에서 끝없이 setState → 50번 넘으면 멈추고 오류
- effect 하나가 오류를 내도 다음 effect 는 실행, 오류는 콘솔에
- 잘못된 인자: callback 이 함수 아님 · deps 가 배열 아님 → TypeError

### useMemo

- 처음 계산한 값을 deps 가 같으면 재사용 (factory 한 번)
- deps 가 바뀌면 다시 계산
- deps 없음 → 매 렌더 다시 계산, [] → 한 번
- 상태가 바뀌어도 관련 없는 memo 는 재계산하지 않음
- factory 가 undefined 를 돌려줘도 재사용 (계산 여부를 따로 기억)
- 잘못된 인자 → TypeError
