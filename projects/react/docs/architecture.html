Phase 1 Phase 2 (점선 = stateless 로 감싸기) core 엔진 (팀 공통, 이름 바꾸지 않기) 실제 DOM

core 안의 화살표는 대표 관계만 그렸습니다. 실제로는 component.js가 vdom · diff · patch · hooks를 모두 쓰고, patch.js도 vdom을 씁니다. 모든 컴포넌트는 vdom.js의 h()로 화면을 만듭니다.

③ Phase 1 흐름 — 테스트 영역의 변경을 실제 영역으로

실제 영역은 Patch로만 바뀝니다. 테스트 영역은 마음대로 고치는 연습장입니다.

페이지를 열 때 · init

  1. 실제 영역 → VDOM₀containerToVdom (들여쓰기 공백 제외)
  2. VDOM₀ → 테스트 영역createElement + 소스 편집기 채우기
  3. 기록history.push(VDOM₀) "초기 상태"

  1. 테스트 영역 → 새 VDOMcontainerToVdom
  2. 비교diff(history.peek(), 새 VDOM) → 0개면 끝
  3. 실제 영역에 반영patch(#real-area, 패치) 실패하면 DOM 그대로
  4. 기록 · 점검history.push → 실제 영역 VDOM == 기록?

뒤로 · 앞으로 · moveTo

  1. 대상 고르기undo() · redo() · go(i)
  2. 실제 영역patch(diff(지금, 대상)) 바뀐 부분만
  3. 테스트 영역대상 VDOM으로 통째로 다시 그림

④ Diff · Patch 내부

Diff는 계산만 하고, Patch는 "먼저 다 찾고 · 다 만들고 · 마지막에 한꺼번에" 적용합니다.

Diff — 노드 한 쌍의 판정 (walk)

Patch — 3단계 (patch)

  1. ① 대상 찾기모든 패치의 노드를 경로([2, 0])로 먼저 찾아 둠. 노드가 없으면 TypeError
  2. ② 새 DOM 미리 만들기CREATE · REPLACE에 넣을 노드를 createElement로. 잘못된 태그면 TypeError
  3. ③ 한꺼번에 적용여기부터는 실패할 일이 없는 DOM 조작만
①②에서 실패하면 실제 DOM은 전혀 바뀌지 않습니다.
경로는 이전 트리 기준이라, 먼저 지우면 뒤 번호가 당겨집니다 → 그래서 ①을 먼저 합니다.

패치 5종류

CREATE부모 끝에 붙이기 REMOVE지우기 REPLACE바꿔 끼우기
TEXT글자만 (노드 재사용) PROPS속성만 (노드 재사용)

⑥ Hooks 저장 구조 — 상태는 어디에 남나

함수는 매번 새로 실행되지만, 값은 인스턴스의 hooks 배열에 남습니다. Hook은 불린 순서로 칸을 찾습니다.

App() 실행 (렌더마다 새로)

prepareHooks(app)        // current = app, hookIndex = 0
useState(loadTodos)      // → hooks[0]
useState("")             // → hooks[1]
…                        // state 10개
useMemo(통계, [todos])    // → hooks[10]
useMemo(보이는 목록, …)   // → hooks[11]
useEffect(저장, [todos])  // → hooks[12]
…                        // effect 4개
finishHooks()            // 개수 16개 그대로인지 확인

FunctionComponent 인스턴스 (계속 살아 있음)

칸kind저장하는 것
0 ~ 9statevalue · setState(한 번만 만듦)
10 ~ 11memovalue · deps
12 ~ 15effectcallback · deps · cleanup · pending
순서가 바뀌면 남의 칸을 읽습니다 → 종류가 다르거나 개수가 달라지면 오류. 자식(stateless) 안에서 Hook을 불러도 오류.

⑦ 이벤트 연결 — VDOM 형식을 지키면서 함수 연결

함수는 표에 넣고, VDOM 속성에는 번호만 남깁니다. 그래서 diff · patch는 함수를 모릅니다.

1. 컴포넌트가 돌려준 것

h("button",
  { class: "btn",
    onClick: () => … },
  "+1")

2. extractHandlers 뒤

VDOM:  { type: "button",
         props: { class: "btn",
           "data-on-click": "0" } }
표:    "0" → { type: "click", fn }

3. 클릭이 일어나면

  1. #root 리스너가 받음종류마다 리스너 1개
  2. 위로 올라가며 찾기data-on-click이 있는 요소
  3. 표에서 함수 실행항상 최신 렌더의 표

⑧ 자료구조

엔진이 주고받는 모양은 이 다섯 가지가 전부입니다.

VNode (팀 공통)

{ type: "div",             // 태그 (소문자)
  props: { id: "box" },     // HTML 속성 그대로
  children: [ VNode | "글자" ] }
"글자"                       // 텍스트 노드는 문자열

루트 VNode (컨테이너)

{ type: "div", props: {}, children: [ …영역 안 내용 ] }

Patch (diff 결과)

{ type: "CREATE",  path: [1], index: 2, node }
{ type: "REMOVE",  path: [0, 2] }
{ type: "REPLACE", path: [2], node }
{ type: "TEXT",    path: [0, 0], value: "반가워" }
{ type: "PROPS",   path: [0],
  set: { class: "big" }, remove: ["title"] }

path = 루트에서 대상까지 자식 번호. 항상 이전 트리 기준.

History 기록

stack = [ { vdom, patchCount, label, time }, … ]
index = 지금 위치 (-1 = 비어 있음)

넣고 꺼낼 때 structuredClone으로 깊은 복사. 읽기만 하면 peek().

FunctionComponent

hooks            [ {kind, …}, … ]   상태 저장소
vdom             마지막으로 반영한 VDOM
handlers         Map("0" → {type, fn})
listenedEvents   리스너를 단 이벤트 종류
updateScheduled  렌더 예약 여부

⑨ 지켜야 할 규칙 (설계가 깨지지 않는 조건)

규칙지키지 않으면
읽기(domToVdom)와 패치(patch)는 같은 공백 규칙으로 자식을 센다"n번째 자식"이 서로 다른 노드를 가리켜 엉뚱한 곳을 고침
Phase 1 실제 영역에는 클래스 · 속성을 붙이지 않는다실제 DOM이 기록과 달라져 다음 diff가 틀어짐
patch는 찾기 · 만들기를 먼저 끝내고 적용한다중간에 실패하면 화면이 반쯤만 바뀜
Hook은 루트에서, 매번 같은 순서로 부른다다른 칸을 읽어 상태가 뒤섞임 (이 구현은 오류로 막음)
VDOM에는 함수를 넣지 않는다 (이벤트는 번호로)diff · patch · 검사가 함수를 처리하지 못함
렌더 중에는 setState를 부르지 않는다렌더가 끝없이 이어짐 (오류로 막음)
core/의 파일 · 함수 이름은 바꾸지 않는다 (팀 규칙)코드리뷰 때 팀원 코드와 1:1 비교가 안 됨
