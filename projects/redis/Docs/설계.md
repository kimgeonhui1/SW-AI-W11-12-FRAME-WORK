## 1. 전체 아키텍처

```
 Client (demo/api_server.py · demo/benchmark.py · curl)
   │  HTTP JSON
   ▼
 API Server ─── mini_redis/server.py      요청 읽기 · 입력 검사 · JSON 응답
   │  메서드 호출
   ▼
 Command Layer ─ mini_redis/store.py      MiniRedis: 만료(TTL) · 락 · 명령 실행
   │  get / set / delete / keys
   ▼
 Storage Engine ─ mini_redis/hashtable.py HashTable: 키 → 값 저장 (dict 사용 X)

 (선택) mini_redis/persistence.py         스냅샷 파일 저장 · 복구
```

| 계층 | 파일 | 담당 역할 | 모르는 것 |
|---|---|---|---|
| Client | `demo/` | 요청 전송, 캐시 활용, 성능 측정 | 저장 방식 |
| API Server | `server.py` | HTTP 경로 → 메서드 호출, 입력 검사, 상태 코드 | 해시 테이블 |
| Command Layer | `store.py` | 만료 처리, 동시성 제어, Redis 규칙(-1 / -2) | HTTP |
| Storage Engine | `hashtable.py` | 해시 · 충돌 처리 · 리사이즈 | 만료 · 락 |

- 아래 계층은 위 계층을 모른다. 그래서 `HashTable` 은 만료를 모르고, `MiniRedis` 는 HTTP를 모른다.
- 각 계층을 따로 테스트할 수 있다 (`test_hashtable` → `test_store` → `test_server`).

## 2. 핵심 데이터 구조

### 2-1. 해시 테이블 (Storage Engine)

```
buckets (리스트, 처음 8칸)
├── [0] []                                    ← 빈 칸
├── [1] [ ["user:1", 항목], ["post:9", 항목] ] ← 충돌: 같은 칸에 줄 세움 (체이닝)
├── [2] [ ["name", 항목] ]
├── ...
└── [7] []
```

- 칸(bucket) = 파이썬 리스트, 칸 안의 항목 = `[key, value]` 리스트 (값을 바꿀 수 있게 튜플이 아닌 리스트).
- `size` = 저장된 항목 수 (`__len__` 이 그대로 돌려준다 → O(1)).

### 2-2. 저장 항목 (Command Layer)

`MiniRedis` 는 해시 테이블의 값 자리에 다음 묶음을 넣는다.

```python
[value, expire_at]      # 예: ["Nameisme", None]  /  ["hi", 12345.67]
```

| 필드 | 뜻 |
|---|---|
| `key` | 데이터 식별자 (해시 테이블의 키, 문자열) |
| `value` | 실제 데이터 (JSON으로 표현되는 값: 문자열 · 숫자 · 불리언 · null · 리스트 · 객체) |
| `expire_at` | 만료 시각 `time.monotonic()` 기준 초. 만료 없음 = `None` |

- **시간 기준은 `time.monotonic()`**: 시스템 시계를 바꿔도(NTP 보정, 수동 변경) 만료가 앞당겨지거나 늦어지지 않는다.
- 단, `monotonic` 값은 프로그램을 다시 켜면 의미가 없다 → 스냅샷에는 "남은 초"로 바꿔 저장한다 (8장).

## 3. 핵심 함수 설계

### 3-1. `HashTable` (`hashtable.py`)

| 함수 | 역할 | 시간 |
|---|---|---|
| `__init__(capacity=8)` | 빈 칸 `capacity` 개 만들기 | O(capacity) |
| `_hash(key)` *(내부)* | 키 → 32비트 정수 (FNV-1a) | O(키 길이) |
| `_index(key)` *(내부)* | `_hash(key) % 칸 수` → 칸 번호 | O(키 길이) |
| `get(key, default=None)` | 값 조회, 없으면 `default` | 평균 O(1) |
| `set(key, value)` | 저장 · 덮어쓰기, 부하율 초과 시 리사이즈 | 평균 O(1) |
| `delete(key)` | 삭제. 지웠으면 `True`, 없던 키면 `False` | 평균 O(1) |
| `keys()` | 모든 키 목록 (새 리스트) | O(n) |
| `__len__()` | 항목 수 | O(1) |
| `_resize(new_capacity)` *(내부)* | 칸을 늘리고 모든 항목 다시 배치 | O(n) |

### 3-2. `MiniRedis` (`store.py`)

| 함수 | 역할 | 반환 |
|---|---|---|
| `__init__()` | 해시 테이블 + 락 준비 | — |
| `set(key, value, ttl=None)` | 저장 · 갱신. `ttl` 초 뒤 만료. **ttl 없이 덮어쓰면 기존 만료는 사라진다** (Redis SET 규칙) | `True` |
| `get(key)` | 조회. 없거나 만료면 `None` | 값 또는 `None` |
| `delete(key)` | 삭제(무효화). 이미 만료된 키는 없는 것 | `True` / `False` |
| `exists(key)` | 키가 있는지 (만료 = 없음) | `True` / `False` |
| `expire(key, ttl)` | 있는 키에 만료 설정 | 키 없으면 `False` |
| `ttl(key)` | 남은 초 (올림). 만료 없음 `-1`, 키 없음 `-2` | 정수 |
| `sweep()` | 만료된 키를 전부 지움 | 지운 개수 |
| `_alive(key)` *(내부, 락 안에서만)* | 항목을 꺼내고, 만료됐으면 지운 뒤 `None` | 항목 또는 `None` |

**`ttl` 입력 규칙** (`set` · `expire` 공통)
- 양의 정수만 받는다 (`1`, `60`). 실제 Redis `EX` · `EXPIRE` 와 같은 초 단위.
- `0` · 음수 · 소수 · 불리언(`True`) · 문자열 → `ValueError`. 서버는 이것을 400으로 바꾼다.

**`ttl` 반환을 올림으로 하는 이유**: 남은 시간이 0.3초여도 키는 아직 살아 있다. 내림이면 살아 있는 키가 `0`을 돌려줘서 "곧 없어짐"과 구별이 안 된다.

## 4. 해시 테이블 결정 (다음 설계 1 · 2 · 3)

| 결정 | 선택 | 이유 |
|---|---|---|
| 처음 크기 | 8칸 (뼈대 기본값) | 작게 시작해 필요할 때만 늘린다 |
| 해시 함수 | **FNV-1a 32비트** (키를 UTF-8 바이트로 바꿔 계산) | 5줄로 짧고 분포가 고르다. 파이썬 내장 `hash()` 는 실행할 때마다 값이 바뀌어(`PYTHONHASHSEED`) 테스트 재현이 어렵다 |
| 충돌 처리 | **Separate Chaining** (칸마다 리스트) | 삭제가 "리스트에서 빼기"로 끝난다. 개방 주소법은 삭제 표시(tombstone)를 따로 관리해야 한다 |
| 리사이즈 | 부하율(`size / 칸 수`) **> 0.75** 이면 칸 **2배** | 칸 하나에 줄 선 항목이 평균 1개 아래로 유지 → 평균 O(1) |
| 줄이기 | 하지 않음 | 지운 뒤 다시 쓰는 경우가 많고, 코드만 늘어난다 |

```python
def _hash(self, key):
    h = 2166136261                      # FNV offset basis
    for byte in key.encode("utf-8"):
        h ^= byte
        h = (h * 16777619) & 0xFFFFFFFF # FNV prime, 32비트로 자름
    return h
```

## 5. 데이터 흐름

### 5-1. 저장 `set(key, value, ttl)`
1. (서버) 요청 경로에서 key, 본문 JSON에서 value · ttl 추출 · 검사 → 틀리면 400
2. (store) 락을 잡는다
3. ttl 이 있으면 `expire_at = monotonic() + ttl`, 없으면 `None`
4. (hashtable) `_index(key)` 로 칸 번호 계산
5. 그 칸의 리스트에서 같은 key 를 찾는다
6. 있으면 값만 바꾼다 (항목 수 그대로)
7. 없으면 `[key, [value, expire_at]]` 를 붙이고 `size += 1`
8. 부하율 > 0.75 이면 칸 2배 리사이즈
9. 락을 놓고 성공 결과 반환 → (서버) 200 `{"ok": true}`

### 5-2. 조회 `get(key)` — 지연 삭제 포함
1. 락을 잡는다
2. 해시 테이블에서 항목을 찾는다 → 없으면 `None`
3. `expire_at` 이 지났으면 **그 자리에서 지우고** `None` (지연 삭제)
4. 살아 있으면 `value` 반환 → (서버) 200, `None` 이면 404

### 5-3. 만료 처리 (다음 설계 5) — 두 방법을 함께 쓴다

| 방법 | 언제 | 없으면 생기는 문제 |
|---|---|---|
| **지연 삭제** | `get` · `exists` · `delete` · `expire` · `ttl` 이 키를 볼 때마다 | `sweep` 주기 사이에 만료된 값이 응답으로 나간다 |
| **주기 삭제** `sweep()` | 서버의 백그라운드 스레드가 **1초마다** | 아무도 다시 읽지 않는 만료 키가 메모리에 영원히 남는다 |

- `sweep` 은 `keys()` 로 전체를 훑는다 (O(n)).
  `shortcut: 키가 수십만 개면 1초마다 전체 훑기가 느려진다 → 그때 실제 Redis처럼 무작위 20개 표본 검사로 바꾼다`

## 6. 캐시 무효화 (다음 설계 6)

- 저장소 쪽 무효화는 `delete(key)` 하나 (+ TTL 자동 만료). 따로 만들 기능은 없다.
- 정책은 `demo/api_server.py` 에서 쓴다 — **Cache-Aside**:
  1. 읽기: 캐시(`GET /keys/item:{id}`) 확인 → 있으면 바로 응답 (hit)
  2. 없으면(miss) 느린 원본 `fetch_item` 조회 → 캐시에 `ttl=60` 으로 저장 → 응답
  3. 원본을 바꾸면 캐시를 `DELETE` → 다음 읽기에서 새 값으로 채워진다
- TTL 은 무효화를 놓쳤을 때의 안전망: 최악이어도 60초 뒤에는 새 값.

## 7. 동시성 (다음 설계 7)

- 서버는 `http.server.ThreadingHTTPServer` → 요청마다 스레드가 따로 돈다. `sweep` 스레드도 동시에 돈다.
- `MiniRedis` 에 **`threading.Lock` 하나**. 모든 공개 메서드는 `with self._lock:` 안에서 실행한다.
- 락이 꼭 필요한 곳 (확인한 뒤 쓰는 동작 — 사이에 다른 스레드가 끼면 틀린다):
  - "만료 확인 → 삭제" (지연 삭제, `sweep`)
  - "같은 키 있음? → 갱신 / 없음 → 삽입" + `size` 증가 + 리사이즈
  - `expire`: "키 있음? → 만료 설정"
- `HashTable` 자체는 락이 없다. 혼자 쓰면 락이 필요 없고, 동시성은 위 계층 책임으로 둔다.
- 락 하나라 요청이 한 줄로 처리되지만, 각 명령이 마이크로초 단위라 HTTP 처리 시간에 비해 무시할 수 있다.
  `shortcut: 락 하나가 병목이 되면(초당 수만 요청) 칸 범위별로 락을 나눈다`

## 8. HTTP API (다음 설계 8)

뼈대 `server.py` 주석의 경로를 그대로 쓴다. 요청 · 응답 본문은 모두 JSON (`Content-Type: application/json; charset=utf-8`).

| 메서드 · 경로 | 요청 본문 | 성공 | 실패 |
|---|---|---|---|
| `GET /keys/{key}` | — | 200 `{"key": k, "value": v}` | 404 `{"error": "not found"}` |
| `PUT /keys/{key}` | `{"value": v, "ttl": 초(선택)}` | 200 `{"ok": true}` | 400 (본문 · ttl 오류) |
| `DELETE /keys/{key}` | — | 200 `{"deleted": true/false}` | — |
| `GET /keys/{key}/ttl` | — | 200 `{"ttl": n}` (-1 / -2 포함) | — |
| `POST /keys/{key}/expire` | `{"ttl": 초}` | 200 `{"ok": true}` | 404 키 없음 · 400 ttl 오류 |
| 그 밖의 경로 | — | — | 404 `{"error": "unknown path"}` |

**입력 검사 (신뢰 경계 — 서버에서 반드시)**
- key: URL 디코딩(`urllib.parse.unquote`), 빈 문자열이면 400.
- 본문: JSON 객체가 아니면 400. `value` 키가 없으면 400 (`null` 은 값으로 허용하지 않는다 — `get` 의 `None` 과 구별이 안 되므로).
- 본문 크기: `Content-Length` 가 1MB 를 넘으면 413. 없거나 숫자가 아니면 400.
- ttl: 3장 규칙. 위반이면 400.
- 서버 안에서 예상 못 한 예외 → 500 `{"error": "internal error"}` (스레드가 죽지 않게).

**실행**: `projects/redis` 에서 `python -m mini_redis.server --port 6380` (기본 `127.0.0.1` — 외부에 열지 않는다).

## 9. 영속성 (다음 설계 9 · 선택)

RDB 방식(스냅샷)을 참고한다. AOF(명령 기록)는 하지 않는다.

| 함수 | 동작 |
|---|---|
| `save_snapshot(store, path)` | 락 안에서 살아 있는 키만 `{key: {"value": v, "ttl_left": 남은 초 또는 null}}` 로 모아 JSON 으로 저장 |
| `load_snapshot(store, path)` | 읽어서 `store.set(key, value, ttl)` 로 다시 넣는다. 파일이 없으면 아무것도 안 함 |

- **원자적 저장**: `path + ".tmp"` 에 다 쓴 뒤 `os.replace` 로 바꾼다 → 쓰는 도중 꺼져도 이전 스냅샷이 남는다.
- 남은 시간을 저장하므로 서버가 꺼져 있던 시간은 만료에 반영되지 않는다 (재시작 시점부터 다시 센다).
  `shortcut: 꺼진 시간까지 반영하려면 저장 시 time.time() 기준 절대 시각을 함께 적는다`
- 저장 시점: 서버 종료(Ctrl+C) 시 한 번. 파일 위치 `projects/redis/data/` (`.gitignore` 에 이미 있음).

## 13. 하지 않는 것

- Redis 의 다른 자료형(List · Set · Hash · Sorted Set), RESP 프로토콜, 복제 · 클러스터, 메모리 한도 · LRU 제거.
- 해시 테이블 줄이기(shrink), AOF.
