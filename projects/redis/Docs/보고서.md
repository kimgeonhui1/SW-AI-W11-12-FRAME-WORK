## 2. 단계별 구현

### 2-1. 해시 테이블 (`hashtable.py`) — Storage Engine

| 결정 | 내용 |
|---|---|
| 해시 | FNV-1a 64비트 모듈 함수 `fnv1a`. 같은 키는 몇 번 실행해도 같은 값 (파이썬 `hash()` 는 실행마다 바뀜) |
| 충돌 | Separate Chaining — 칸마다 `[key, value]` 리스트. 삭제는 리스트에서 빼면 끝 |
| 리사이즈 | 부하율 0.75 **초과** 시 칸 2배. 줄이기는 하지 않음. 칸 수는 `capacity()` |
| 입력 | 키가 문자열이 아니면 `TypeError`, capacity 가 1 이상의 정수가 아니면 `ValueError` |

**만들면서 설계에 더한 것**
- `__contains__` — `store.py` 가 `key in table` 을 쓴다. `None` 값도 "있음" 으로 구별된다.
- `key.encode("utf-8", "surrogatepass")` — 짝 없는 반쪽 문자(`"\ud800"`)도 파이썬 `str` 이라 받아야 하는데, 그냥 utf-8 로 바꾸면 `UnicodeEncodeError` 가 난다.

**테스트 20개**: 기본 동작, 같은 칸에 일부러 모은 키(충돌), 0.75 경계(6/8 은 그대로, 7/8 에서 16칸), 키 300종류로 저장 · 삭제 · 조회를 섞은 무작위 2,000번을 `dict` 와 매번 대조, 한글 · 빈 문자열 · 반쪽 문자 키, FNV-1a 64비트 표준 값.

### 2-2. 저장소 (`store.py`) — Command Layer

| 결정 | 내용 |
|---|---|
| 저장 구조 | 해시 테이블 2개 — `_data`(키 → 값) · `_expires`(키 → 만료 시각, ttl 을 준 키만) |
| 시간 | `MiniRedis(clock=time.monotonic)` — 컴퓨터 시계를 바꿔도 만료가 꼬이지 않고, 테스트는 가짜 시계를 넣는다 |
| 만료 | 지연 삭제(`_alive` — 명령 6개가 모두 거침) + 주기 삭제(`sweep` — 만료 키만 훑음). 만료 시각과 **같은** 순간도 만료 |
| ttl 입력 | 0.001초 이상의 유한한 숫자 (정수 · 소수). 0 · 음수 · `NaN` · `Infinity` · `True` · 문자열 → `ValueError`, 기존 값은 그대로 |
| ttl 반환 | 올림 (0.3초 남으면 1). 만료 없음 -1, 키 없음 -2 |
| SET 규칙 | ttl 없이 덮어쓰면 기존 만료가 사라진다 (실제 Redis) |
| 추가 API | `get_with_ttl` (값 · ttl 을 락 하나 안에서 함께), `__len__` |
| 동시성 | `threading.Lock` 하나. 공개 메서드 9개 모두 락 안 |

**만들면서 정한 것**
- `10**400` 같은 너무 큰 정수 ttl 은 `isfinite` 에서 `OverflowError` 가 나므로 잡아서 `ValueError` 로 바꾼다.

**테스트 23개**: ttl 규칙 · 올림 · 경계 · 소수 ttl, `get_with_ttl` · `len`, 명령 6개가 각각 만료 키를 두 테이블에서 지우는지, `sweep` 개수, 잘못된 ttl 13가지, 스레드 8개 동시 저장(키 4,000개 모두 남음), 저장 · 삭제 · `sweep` 동시 실행.

### 2-3. HTTP 서버 (`server.py`) — API Server

| 경로 | 성공 | 실패 |
|---|---|---|
| `GET /keys/{key}` | 200 `{"key", "value", "ttl"}` | 404 |
| `PUT /keys/{key}` | 200 `{"ok": true}` | 400 · 413 · 408 |
| `DELETE /keys/{key}` | 200 `{"deleted": bool}` | — |
| `GET /keys/{key}/ttl` | 200 `{"ttl": n}` | — |
| `POST /keys/{key}/expire` | 200 `{"ok": true}` | 404 · 400 |
| `GET /health` | 200 `{"keys": n}` | 405 |
| 그 밖 | — | 404 경로 없음 · 빈 키 / 405 메서드 다름 (`PATCH` · `OPTIONS` 포함) |

**입력 검사 (신뢰 경계)**: Content-Length 없음 · 숫자 아님 → 400, 1MB 초과 → 413, 10초 안에 본문 못 받음 → 408, 잘못된 JSON · `NaN` · `Infinity` · 너무 깊은 중첩 · 반쪽 문자 · 객체 아님 · `value` 없음 · `null` → 400, 잘못된 ttl → 400 (ttl 규칙은 `store.py` 한 곳에만 있고 서버는 `ValueError` 를 400 으로 바꾼다), 예상 못 한 오류 → 500 이고 서버는 계속 동작.

**만들면서 발견한 것**
- Python 3.14 는 `[[[[...]]]]` 처럼 아주 깊은 JSON 을 **읽기는 하는데**, 응답으로 다시 쓸 때 `RecursionError` 가 난다. 반쪽 문자도 UTF-8 로 못 써서 응답이 끊긴다. 그대로 두면 "저장은 성공, 조회는 실패" 가 된다 → 저장 전에 UTF-8 JSON 으로 한 번 써 보고 400 으로 거부.
- **413 을 보낼 때 연결이 강제로 끊기던 문제** (dev 코드 · 테스트에서도 실패하던 것): 본문을 읽지 않은 채 연결을 닫으면 운영체제가 RST 를 보내, 본문을 보내던 클라이언트는 413 을 받기 전에 `Connection reset` 을 본다 → 응답 전에 본문을 읽어서 버린다 (최대 16MB).
- 408 제한 시간을 클래스 속성으로 두면 import 때 한 번만 읽혀서, 테스트가 `REQUEST_TIMEOUT` 을 바꿔도 적용되지 않았다 → 연결마다 `setup()` 에서 모듈 값을 읽는다.
- 키 안의 `/` 는 `%2F` 로 보내야 한다. 경로를 `/` 로 먼저 나눈 뒤 조각마다 디코딩해서 키의 `/` 가 경로 구분자로 오해되지 않게 했다.
- 주기 삭제는 `MiniRedisServer` 가 `SWEEP_INTERVAL`(1초)마다 `sweep` 하는 스레드를 함께 띄우고, `server_close()` 때 멈춘다.
- **동시 접속 끊김** (검증 중 발견, 9장): 표준 라이브러리 기본 연결 대기열(`request_queue_size = 5`)로는 클라이언트 수십 개가 한꺼번에 접속하면 넘친 연결이 `Connection reset` 으로 끊겼다 → `request_queue_size = 128`.

**테스트 22개**: 클라이언트 50개 동시 접속, 400 이유별 한국어 문구, 경로표 전부(GET 응답 ttl · 소수 ttl · `/health` · `PATCH` · `OPTIONS` 포함), 잘못된 요청 약 30가지, 실제로 1MB 넘게 보낸 본문(413), 보내다 멈춘 클라이언트(408), 한글 · `/` · 이모지 키, 500 뒤 서버 생존, 아무도 안 읽은 키가 실제 1초 주기로 지워지는지, 스레드 5개 동시 요청.

### 2-4. 데모 (`demo/`) — Client

- `api_server.py` — **dev 파일을 그대로 쓴다.** Cache-Aside + 버전 키(`item:{id}:v{n}`). 지금 버전 키가 있으면 HIT, 없으면 원본을 읽고 0.2초 뒤 도착, "읽은 버전 == 지금 버전" 일 때만 60초 저장(MISS). `PUT /items/{id}` 로 가격을 바꾸면 버전이 올라 옛 키는 더 이상 읽히지 않고(무효화), 옛 키 삭제 결과를 `old_cache_deleted` 로 돌려준다. Mini Redis 가 꺼져 있거나 이상한 응답을 주거나 저장이 실패하면 원본으로 응답(BYPASS).
- `benchmark.py` — 제 구현 (dev 에서는 TODO). `python -m demo.benchmark` 한 줄이면 Mini Redis · 데모 서버를 프로그램 안에서 빈 포트로 띄워 잰다(`create_demo_server` 사용). 이미 띄운 서버는 `--api`.

**테스트 10개**: MISS → HIT 이고 HIT 가 더 빠름, 캐시에 ttl 60초 이하, `cache=off` 는 저장 안 함, 수정 뒤 새 가격 · 옛 버전 키 정리 · `old_cache_deleted`, 느린 읽기 도중 수정돼도 옛 값이 캐시에 남지 않음, 404 · 400, Mini Redis 장애 시 BYPASS, `measure`.

## 5. 설계 점검

**맞는 것 (코드로 확인)**
- 뼈대 함수 23개 이름 모두 같음 (`ast` 로 `25c050c` 와 대조. 해시 테이블 6 · 저장소 8 · 서버 2 · 영속성 2 · 데모 3 · 벤치마크 2). 매개변수가 다른 곳은 `MiniRedis.__init__(self, clock=time.monotonic)` 하나 — 선택 매개변수라 `MiniRedis()` 는 그대로 동작.
- 계층 경계: `hashtable.py` 는 아무것도 import 안 함, `store.py` 에 HTTP · JSON 없음, `server.py` 는 해시 테이블을 직접 안 만짐, `demo/api_server.py` 는 `mini_redis` 를 import 안 하고 HTTP 로만 씀.
- 공개 메서드 9개 모두 락 안, 지연 삭제는 명령 6개 모두 `_alive` 경유, 외부 패키지 없음.

**문서를 고친 곳 (코드에 맞춤, 첫 점검 때)**
1. 2-2장 value 설명 — `MiniRedis` 는 `None` 을 받지만 HTTP 는 `null` 거부.
2. 2-2장 스냅샷 참조 — 8장 → 9장.
3. 10장 — 해시 테이블 무작위 테스트 "1,000개" → "키 300종류 · 2,000번".

**알고 둔 차이**
- `get_item_cached(item_id)` 는 `(아이템, "HIT" | "MISS" | "BYPASS")` 두 값을 돌려준다 (dev 와 같음).
- `benchmark.py` 는 서버를 직접 띄우려고 `mini_redis` 를 import 한다 (Client 계층의 예외). 저장소를 직접 만지지는 않는다.

## 6. 알려진 한계 (`shortcut:` 주석)

| `store.sweep` | 1초마다 만료 키를 전부 훑음 (O(만료 키 수)) | 만료 키가 수십만 개 → Redis 처럼 무작위 20개 표본 검사 |
